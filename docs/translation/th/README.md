**Omega-Stress** เป็นแอปพลิเคชันเทอร์มินัลในเครื่อง (TUI [Textual](https://github.com/Textualize/textual) + CLI ที่เขียนสคริปต์ได้) ที่ควบคุมการทดสอบโหลด HTTP อย่างมีกรอบและใช้ซ้ำได้: โปรไฟล์ที่ตรึงไว้ ประวัติ การรันซ้ำ การส่งออกแบบละเอียด (JSON/CSV/HTML) และขอบเขตความปลอดภัยที่ชัดเจน

โปรเจกต์นี้ยึดหลัก **Clean Architecture** โดยแยกโดเมนธุรกิจ การประสานงาน โครงสร้างพื้นฐาน และส่วนติดต่อผู้ใช้ออกจากกันอย่างชัดเจน

### เป้าหมาย

## สิ่งที่ Omega-Stress ทำ (เป้าหมาย V1)

- กลุ่มการทดสอบแบบมีการควบคุมสามกลุ่ม: **การทดสอบคำขอ** (ปริมาณงาน) **การทดสอบการเชื่อมต่อ** (ความพร้อมกัน) **การทดสอบโหลด** (เพิ่มขึ้นทีละขั้น)
- **8 ระดับความเข้ม** (เบามาก/ต่ำ/ปานกลาง/สูง/แรง/รุกหนัก/รุนแรง/สูงสุด) พร้อมแบบจำลองการตรวจล่วงหน้า 3 ขั้น (ไม่เคยบังคับ / บังคับแบบเลือกได้ / บังคับเสมอ — ดู [ค่าของการทดสอบ](#ค่าของการทดสอบ))
- **สองโหมดระยะเวลา**: กำหนดเอง (1 ถึง 5 นาที จำกัดตามระดับ) หรือ **โปรไฟล์ที่มีชื่อ D1-D6** (ระยะเวลารวมคงที่ พร้อมช่วงวอร์มอัป/ไต่ระดับ/คงที่/ผ่อนลง — ดู [โปรไฟล์ระยะเวลา D1-D6](#โปรไฟล์ระยะเวลา-d1-d6-โหมดโปรไฟล์))
- **โหมดความปลอดภัย** (เปิดเป็นค่าเริ่มต้น ปิดได้ทุกครั้งที่เริ่ม): ตัวป้องกัน CPU/หน่วยความจำของเครื่องโฮสต์ แยกจากเกณฑ์ที่ป้องกันเป้าหมายที่ถูกทดสอบ — ดู [โหมดความปลอดภัย](#โหมดความปลอดภัย)
- **การปรับเทียบในเครื่องแบบถาวร**: วัดความสามารถจริงของเครื่องโฮสต์ (ไม่ใช่ของเป้าหมาย) ผ่านเซิร์ฟเวอร์ลูปแบ็กในเครื่อง ด้วยโหลดที่เพิ่มขึ้นเป็นขั้น — ดู [การปรับเทียบในเครื่อง](#การปรับเทียบในเครื่อง)
- โปรไฟล์ที่ตรึงไว้ ใช้ซ้ำได้ และบันทึกในประวัติ — **ไม่บังคับ**: การทดสอบรันในโหมดกำหนดเองได้ดีพอกันโดยไม่ต้องมีโปรไฟล์ เพียงเลือกหรือกรอกเป้าหมายโดยตรง
- ต้องยืนยันการได้รับอนุญาตอย่างชัดเจนก่อนรันกับเป้าหมายที่ยังไม่ได้ปักหมุด
- เกณฑ์หยุดอัตโนมัติ ไม่มีโหลดที่ไร้ขอบเขต
- การส่งออก JSON/CSV/HTML แบบละเอียด (ขั้น ตัวชี้วัดต่อช่วง ผลสรุป การวินิจฉัย)
- โหมด CLI แบบไม่โต้ตอบสำหรับงานอัตโนมัติ (cron, CI) ที่เรียกใช้กรณีการใช้งานเดียวกับ TUI ทุกประการ
- ปรับให้เข้ากับเทอร์มินัลโดยอัตโนมัติ (ธีม + โปรไฟล์การแสดงผลที่ลดทอนได้)

## สิ่งที่โปรเจกต์ไม่ทำ

- ไม่ได้ทดแทนเครื่องมือสแกนเครือข่าย — ถ้อยคำและจุดยืนของผลิตภัณฑ์คือ “การทดสอบโหลด” โดยเจตนา ไม่ใช่ “การสแกน”
- ไม่ได้ใช้เอนจินโหลดภายนอกใด ๆ (k6 ฯลฯ) — สร้างโหลดเองด้วย `httpx`/asyncio
- ไม่เริ่มการรันใดเลยหากไม่มีขอบเขตและไม่มีการยืนยันการได้รับอนุญาต
- ไม่ใช่เครื่องมือโหลดแบบกระจาย: การสร้างโหลดทำงานบนเครื่องเดียว ในโปรเซสเดียว — ดู [ข้อจำกัดที่ทราบ](#ข้อจำกัดที่ทราบ)

## ความสามารถ

- **สามกลุ่มการทดสอบ** แต่ละกลุ่มมี 8 ระดับความเข้ม (เบามาก/ต่ำ/ปานกลาง/สูง/แรง/รุกหนัก/รุนแรง/สูงสุด) — ค่าที่แน่นอนของแต่ละระดับดูได้จากตาราง [จุดอ้างอิงโหลด](#ค่าของการทดสอบ)
- **โปรไฟล์การทดสอบที่ตรึงไว้**: ชื่อ เป้าหมาย กลุ่ม ความเข้ม ระยะเวลา เกณฑ์ข้อผิดพลาด — สร้างครั้งเดียว รันซ้ำได้เหมือนเดิมทุกประการจาก TUI หรือ CLI
- **โปรไฟล์ระยะเวลาที่มีชื่อ D1-D6** (โหมด “โปรไฟล์”) ทางเลือกแทนโหมดกำหนดเอง: ระยะเวลารวมคงที่ (1 ถึง 120 นาที) พร้อมวอร์มอัป/ไต่ระดับ/คงที่/ผ่อนลง ซึ่งยังจำกัดระดับที่ใช้ได้ด้วย — ดู [โปรไฟล์ระยะเวลา D1-D6](#โปรไฟล์ระยะเวลา-d1-d6-โหมดโปรไฟล์)
- **โหมดความปลอดภัย** ติ๊กไว้เป็นค่าเริ่มต้นบนทุกหน้าจอเริ่มการทดสอบ: หยุดการทดสอบหากเครื่องโฮสต์ (ไม่ใช่เป้าหมาย) ดูเหมือนตกอยู่ในอันตราย ปิดได้เมื่อเข้าใจผลที่ตามมา พร้อมข้อความเตือนที่เทียบระดับที่เลือกกับผลการปรับเทียบครั้งล่าสุด — ดู [โหมดความปลอดภัย](#โหมดความปลอดภัย)
- **การปรับเทียบในเครื่องแบบถาวร**: วัดว่าเครื่องรับไหวจริงเท่าใด (โหลด 7 ขั้นที่เพิ่มขึ้นต่อเซิร์ฟเวอร์ลูปแบ็กในเครื่องที่มีมาให้) เปิดดูได้จากหน้าจอการปรับเทียบ — ดู [การปรับเทียบในเครื่อง](#การปรับเทียบในเครื่อง)
- **เป้าหมายที่ปักหมุด**: ที่อยู่ที่ปักหมุดแล้วไม่ต้องติ๊กการอนุญาตซ้ำทุกครั้ง เป้าหมายล่าสุดที่ไม่ได้ปักหมุดยังมองเห็นได้ (สูงสุด 10 รายการ) โดยไม่ได้รับอนุญาตโดยปริยาย เป้าหมายที่ปักหมุดใช้ได้สองแบบที่เป็นอิสระต่อกัน: ใช้โดยตรงเพื่อเริ่มการทดสอบในโหมดกำหนดเองโดยไม่มีโปรไฟล์ หรือใช้เป็นเป้าหมายเริ่มต้นเมื่อสร้างโปรไฟล์ที่ตรึงไว้
- **ประวัติครบถ้วน**: ทุกการรันถูกบันทึก (ผลสรุป ตัวชี้วัด ลำดับเหตุการณ์ต่อช่วง โหมดความปลอดภัยที่ใช้) การรันที่ผูกกับโปรไฟล์ที่ตรึงไว้สามารถเล่นซ้ำได้เหมือนเดิม
- **การส่งออกแบบละเอียด** เป็น JSON (ข้อมูลดิบนำเข้าซ้ำได้) CSV (วิเคราะห์แบบตาราง) หรือ HTML (รายงานอ่านง่าย เลือกธีมได้จาก 10 ชุดสีของโปรเจกต์) รายงาน HTML เขียนด้วยภาษาที่เลือกในการตั้งค่า (“ภาษาของการส่งออก” ค่าเริ่มต้นคือภาษาของอินเทอร์เฟซ) ส่วน JSON และ CSV ยังคงเป็นข้อมูลและไม่ถูกแปล
- **การตรวจล่วงหน้า** อัตโนมัติและบังคับก่อนการทดสอบระดับรุนแรง/สูงสุดทุกครั้ง เลือกได้ (แต่ปลดล็อกระยะเวลาที่ยาวขึ้น) สำหรับระดับแรง/รุกหนัก มีช่วงเวลาที่ใช้ได้ (24 ชม.)
- **ติดตามสด** การทดสอบที่กำลังรัน: แถบความคืบหน้าพร้อมการนับถอยหลังที่เชื่อถือได้ (เวลาที่เหลือคำนวณโดยตรง ไม่ใช่การประมาณ) ปริมาณงาน/ข้อผิดพลาด/ค่าหน่วง p95 อัปเดตทุกช่วง หยุดเองได้โดยไม่ต้องออกจากแอป
- **การตั้งค่าแบบรวมศูนย์**: ธีม (10 ชุดสี Omega + ธีมในตัวของ Textual ทั้งหมด รวม 31 ธีมผ่านพาเลตคำสั่ง) โปรไฟล์การแสดงผล (อัตโนมัติหรือบังคับ) โฟลเดอร์ส่งออกและภาพหน้าจอ การล้างเป้าหมาย/ประวัติ
- **ความช่วยเหลือในตัว** (แป้น `a`): แป้นลัด คำอธิบายแต่ละหน้าจอ (รวมถึงการปรับเทียบและโหมดความปลอดภัย) ตารางอ้างอิงค่าโหลด และตารางโปรไฟล์ระยะเวลา D1-D6
- **CLI ที่เขียนสคริปต์ได้** (`omega-stress profile|run|history|export|calibrate ...`) มีกรณีการใช้งานเดียวกับ TUI ทุกประการ พร้อมเอาต์พุต `--json` สำหรับงานอัตโนมัติ
- **ปรับให้เข้ากับเทอร์มินัลโดยอัตโนมัติ**: ตรวจจับตระกูลและขนาดเมื่อเริ่มโปรแกรม แล้วปรับธีมและความละเอียดของการแสดงผลให้เหมาะสม (ดู [เทอร์มินัลที่รองรับ](#เทอร์มินัลที่รองรับ))

## สถาปัตยกรรม

Clean Architecture + Ports & Adapters ใน 9 แพ็กเกจ (`app/`, `core/`, `domain/`, `application/`, `ports/`, `infrastructure/`, `interfaces/`, `plugins/`, `shared/`)
รายละเอียดทั้งหมด: `ARCHITECTURE.md`

```text
src/omega_stress/
├── app/              การเริ่มระบบและคอนเทนเนอร์ฉีดการพึ่งพา (เชื่อมด้วยมือ ไม่ใช้เฟรมเวิร์ก DI)
├── core/             คำศัพท์ร่วม: ชนิดแจกแจง ข้อยกเว้นราก Result/Ok/Err ความสามารถของระบบ
├── domain/           ตรรกะทางธุรกิจล้วน: โหลด โปรไฟล์ การรัน เป้าหมาย ธีม เทอร์มินัล — ไม่มี I/O
├── application/      การประสานงาน: commands (การกระทำ) queries (การอ่าน) ไปป์ไลน์การทำงาน (guards/hooks)
├── ports/            สัญญา Protocol/ABC ที่ตัวแปลงคาดหวัง (ที่เก็บข้อมูล ตัวส่งออก ตัวสร้างโหลด...)
├── infrastructure/   การทำงานจริง: SQLite ตัวส่งออก JSON/CSV/HTML ตัวสร้าง httpx/asyncio การตรวจจับเทอร์มินัล ตัวตรวจระบบ
├── interfaces/       ตัวแปลงการแสดงผลสองตัวที่เป็นอิสระ: TUI (Textual) และ CLI (argparse)
├── plugins/          จุดขยายที่สงวนไว้ (การโหลดปลั๊กอิน) — มีโครงแล้ว ยังไม่ได้ทำใน V1
└── shared/           เครื่องมือร่วมที่ไม่ขึ้นกับธุรกิจ (นาฬิกาที่ฉีดได้ การสร้างตัวระบุ)
```

### หลักการออกแบบ

- `domain/` ไม่มีทั้ง I/O และการพึ่งพาโครงสร้างพื้นฐาน — ตรรกะทางธุรกิจล้วน ทดสอบได้ทั้งหมดโดยไม่ต้องใช้ mock
- `application/` ประสานกรณีการใช้งานผ่านโดเมนและพอร์ต ไม่ใช้คลาสจริงใน `infrastructure/` โดยตรง
- `infrastructure/` ทำงานตามพอร์ตโดยไม่ถูก `application/` หรือ `domain/` นำเข้าโดยตรงเลย — มีเพียง `interfaces/` และ `app/` ที่อ้างถึง
- `interfaces/` ห้ามเรียก `infrastructure/` หรือ `subprocess` โดยตรง: ต้องผ่าน `application/` (commands/queries) และคอนโทรลเลอร์ของตัวเองเท่านั้น
- `ports/` กำหนดสัญญาที่ตัวแปลงคาดหวัง (Protocol) ไม่ใช่การทำงานจริง
- `core/` รวบรวมคำศัพท์ที่ทุกชั้นใช้ร่วมกัน โดยไม่ฝังกฎธุรกิจที่มีตัวเลข (เกณฑ์ ระยะเวลา พรีเซ็ต — อยู่ใน `domain/*/policies.py` เสมอ)

Dependency Rule (จากชั้นนอกเข้าสู่ชั้นในเท่านั้น) และการแยกเทคโนโลยีภายนอก (`textual`, `sqlite3`, `httpx`, `jinja2` แต่ละตัวจำกัดอยู่ที่จุดเข้าที่กำหนด) ถูกตรวจโดยอัตโนมัติทุกครั้งที่รัน `lint-imports` (ดู [การทดสอบและคุณภาพ](#การทดสอบและคุณภาพ))

### การใช้ CLI

```bash
omega-stress profile list                                     # แสดงรายการโปรไฟล์
omega-stress profile create --name "สำรวจ API" --target-id t-1 \
    --family request --level bas --duration-minutes 1 --max-error-rate 0.05
omega-stress profile freeze <profile-id>                       # ตรึงโปรไฟล์

# ต้องตรวจล่วงหน้าก่อนรันระดับรุนแรง/สูงสุดทุกครั้ง (เลือกได้สำหรับแรง/รุกหนัก)
omega-stress run precheck --target-id t-1 --target-url https://exemple.org --confirm

omega-stress run request --target-id t-1 --target-url https://exemple.org \
    --level bas --duration-minutes 1 --max-error-rate 0.05 --confirm
omega-stress run connection --target-id t-1 --target-url https://exemple.org \
    --level moyen --duration-minutes 3 --max-error-rate 0.05 --confirm
omega-stress run ramp --target-id t-1 --target-url https://exemple.org \
    --level puissant --duration-minutes 3 --max-error-rate 0.05 --confirm --precheck-validated

# โหมดโปรไฟล์ D1-D6 แทน --duration-minutes (ใช้ร่วมกันไม่ได้)
# D4 (resilience) อนุญาตระดับรุกหนักโดยไม่มีเงื่อนไข และระดับรุนแรงเมื่อยืนยันแบบเข้มงวด
omega-stress run request --target-id t-1 --target-url https://exemple.org \
    --level violent --duration-preset d4 --max-error-rate 0.05 --confirm \
    --precheck-validated --confirmation-text JE_CONFIRME_LA_CIBLE_AUTORISEE

# --unsafe ปิดโหมดความปลอดภัย (ตัวป้องกัน CPU/หน่วยความจำในเครื่อง) ค่าเริ่มต้นไม่ใส่
omega-stress run connection --target-id t-1 --target-url https://exemple.org \
    --level violent --duration-minutes 1 --max-error-rate 0.05 --confirm \
    --precheck-validated --unsafe

omega-stress run replay <run-id> --confirm                     # เล่นซ้ำการรันที่ผูกกับโปรไฟล์ที่ตรึงไว้

omega-stress history list                                      # ประวัติการรัน
omega-stress history show <run-id>                              # รายละเอียดของการรัน

omega-stress export <run-id> --format html --destination var/exports --theme omega-base

omega-stress calibrate run                                      # ปรับเทียบเครื่องนี้
omega-stress calibrate show                                     # แสดงผลการปรับเทียบล่าสุดที่ทราบ
```

ค่าของ `--level` (`faible`, `bas`, `moyen`, `haut`, `puissant`, `agressif`, `violent`, `maximum`) และข้อความยืนยันยังคงเป็นภาษาฝรั่งเศส เช่นเดียวกับส่วนอื่นของบรรทัดคำสั่ง

`--confirm` คือสิ่งที่เทียบเท่ากับช่องติ๊กการอนุญาตใน TUI บนบรรทัดคำสั่ง: จำเป็นสำหรับทุกเป้าหมายที่ยังไม่ได้ปักหมุดว่าได้รับอนุญาต หาก `--target-id`/`--target-url` เหมือนกันหมายถึงเป้าหมายที่กำหนดเอง (ไม่ได้ปักหมุด) ใช้ตัวระบุของเป้าหมายที่ปักหมุดแล้วเพื่อไม่ต้องใส่ `--confirm` ทุกครั้ง

เพิ่ม `--json` ให้ `history`/`export`/`calibrate` เพื่อให้ได้เอาต์พุตที่เครื่องอ่านได้ สำหรับใช้ใน cron/CI

### ลำดับการใช้งานทั่วไป

1. เมื่อเปิดครั้งแรก หน้าจอหลักจะเสนอ: โปรไฟล์ การทดสอบคำขอ การทดสอบการเชื่อมต่อ การทดสอบโหลด ประวัติ เป้าหมาย การปรับเทียบ การตั้งค่า ช่วยเหลือ
2. บนหน้าจอการทดสอบ ยังเลือกโปรไฟล์ที่ตรึงไว้ (ไม่บังคับ) ได้ที่ด้านบน: มีสองวิธีในการระบุเป้าหมายและเงื่อนไข ซึ่งไม่ใช้ร่วมกันในการเริ่มครั้งเดียว —
   - **ใช้โปรไฟล์**: การเลือกโปรไฟล์จะกรอกเป้าหมาย/ความเข้ม/ระยะเวลา/เกณฑ์ข้อผิดพลาดไว้ให้ และช่องเป้าหมายที่กำหนดเองจะหายไป (ไม่จำเป็นแล้ว) ค่าที่กรอกไว้ยังแก้ไขได้ก่อนเริ่ม
   - **ไม่ใช้โปรไฟล์ (โหมดกำหนดเอง)**: เลือกเป้าหมายที่ปักหมุด/ล่าสุดจากรายการหรือกรอกใหม่ ติ๊กการอนุญาตหากยังไม่ได้ปักหมุดว่าได้รับอนุญาต แล้วตั้งความเข้ม/ระยะเวลา (กำหนดเองหรือโปรไฟล์ระยะเวลา D1-D6)/เกณฑ์ข้อผิดพลาดด้วยตนเอง

   ทั้งสองกรณี: เปิดโหมดความปลอดภัยไว้หรือปิดเมื่อเข้าใจผลที่ตามมา ตรวจล่วงหน้าหากระดับนั้นกำหนด แล้วจึงเริ่มการทดสอบ
3. ผลลัพธ์แสดงทันที (ผลสรุป ตัวชี้วัด ลำดับเหตุการณ์) โดยไม่ต้องไปที่ประวัติ — หน้าจอนี้เสนอการส่งออกได้โดยตรง
4. สามารถตรึงโปรไฟล์ไว้เพื่อรันการทดสอบเดิมซ้ำได้เหมือนเดิมภายหลัง จากหน้าจอโปรไฟล์หรือเล่นซ้ำจากประวัติ

| การทดสอบโหลด (เพิ่มขึ้นทีละขั้น) | แรง | ปริมาณงาน แบบไต่ระดับ | สูงสุด 6000 คำขอ/นาที | เลือกได้ | 1 ถึง 3 นาที (5 เมื่อผ่านการตรวจล่วงหน้า) |
| การทดสอบโหลด (เพิ่มขึ้นทีละขั้น) | รุกหนัก | ปริมาณงาน แบบไต่ระดับ | สูงสุด 10,000 คำขอ/นาที | เลือกได้ | 1 ถึง 3 นาที (5 เมื่อผ่านการตรวจล่วงหน้า) |
| การทดสอบโหลด (เพิ่มขึ้นทีละขั้น) | รุนแรง | ปริมาณงาน แบบไต่ระดับ | สูงสุด 15,000 คำขอ/นาที | **บังคับ** | 1 ถึง 3 นาทีเท่านั้น |
| การทดสอบโหลด (เพิ่มขึ้นทีละขั้น) | สูงสุด | ปริมาณงาน แบบไต่ระดับ | สูงสุด 20,000 คำขอ/นาที | **บังคับ** | 1 ถึง 3 นาทีเท่านั้น |

- **ตรวจล่วงหน้า: ไม่**: การทดสอบเริ่มทันที ไม่มีเงื่อนไขเรื่องระยะเวลา
- **ตรวจล่วงหน้า: เลือกได้** (แรง/รุกหนัก): การทดสอบเริ่มได้โดยไม่ต้องตรวจล่วงหน้า (ระยะเวลา 1-3 นาที) แต่เมื่อผ่านการตรวจล่วงหน้าจะปลดล็อกระยะเวลา 4-5 นาทีด้วย
- **ตรวจล่วงหน้า: บังคับ** (รุนแรง/สูงสุด): การทดสอบจะไม่เริ่มหากยังไม่ผ่านการตรวจล่วงหน้า ระยะเวลายังคงจำกัดที่ 3 นาทีแม้ผ่านการตรวจล่วงหน้าแล้ว (ในกรณีนี้การตรวจล่วงหน้ากำหนดสิทธิ์เข้าถึงระดับ ไม่ใช่การขยายระยะเวลา)

คอลัมน์ “ระยะเวลาที่ใช้ได้” ด้านบนครอบคลุมเฉพาะ **โหมดกำหนดเอง** (สูงสุด 5 นาที) เกินกว่านั้น มีเพียง [โหมดโปรไฟล์ D1-D6](#โปรไฟล์ระยะเวลา-d1-d6-โหมดโปรไฟล์) ที่อนุญาตให้ทดสอบนานขึ้น (สูงสุด 120 นาที) — แต่ละโปรไฟล์ D1-D6 กำหนดเองว่าระดับใดยังใช้ได้ที่ระยะเวลานั้น (`free_max_level`/`reinforced_level` ดูตารางของโปรไฟล์):

| ระดับ | ระยะเวลาสูงสุดในโหมดกำหนดเอง | ระยะเวลาสูงสุดผ่านโปรไฟล์ D1-D6 |
|---|---|---|
| เบามาก / ต่ำ / ปานกลาง / สูง | 5 นาที | 120 นาที (D6 เฉพาะการเชื่อมต่อ/โหลด); 60 นาทีสำหรับคำขอ (D5 เพราะ D6 ใช้กับกลุ่มนี้ไม่ได้) |
| แรง | 5 นาที (3 นาทีหากไม่ตรวจล่วงหน้า) | 120 นาทีเมื่อยืนยันแบบเข้มงวด (D6 การเชื่อมต่อ/โหลด) หรือ 60 นาทีหากไม่ยืนยัน (D5) |
| รุกหนัก | 5 นาที (3 นาทีหากไม่ตรวจล่วงหน้า) | 60 นาทีเมื่อยืนยันแบบเข้มงวด (D5) หรือ 30 นาทีหากไม่ยืนยัน (D4) |
| รุนแรง | 3 นาที (บังคับตรวจล่วงหน้า) | 30 นาทีเมื่อยืนยันแบบเข้มงวด (D4) หรือ 15 นาทีหากไม่ยืนยัน (D3) |
| สูงสุด | 3 นาที (บังคับตรวจล่วงหน้า) | สูงสุด 5 นาที (เฉพาะ D1/D2 — ไม่มีโปรไฟล์ D3-D6 ใดเสนอระดับสูงสุด แม้จะยืนยันแล้วก็ตาม) |

ตารางเดียวกันนี้ดูได้โดยตรงในแอป (ช่วยเหลือ → จุดอ้างอิงโหลด) ซึ่งสร้างจากค่าอ้างอิงชุดเดียวกันเสมอ (`domain/load/presets.py`, `domain/load/policies.py`) — ไม่เคยคัดลอกด้วยมือ

> สำหรับการทดสอบโหลดใน **โหมดกำหนดเอง** ช่วงไต่ระดับและช่วงคงที่จะถูกปรับตามระยะเวลาที่เลือกโดยอัตโนมัติ (คงสัดส่วนของพรีเซ็ตไว้): การทดสอบ 1 นาทีจะผ่านทั้งเส้นโค้งตั้งแต่ 0 ถึงจุดสูงสุด ไม่ใช่แค่ช่วงต้น ใน **โหมดโปรไฟล์ D1-D6** การแบ่งช่วงวอร์มอัป/ไต่ระดับ/คงที่/ผ่อนลงของแต่ละโปรไฟล์ให้การรับประกันเดียวกันนี้อยู่แล้ว — ดู [โปรไฟล์ระยะเวลา D1-D6](#โปรไฟล์ระยะเวลา-d1-d6-โหมดโปรไฟล์)

### การนำทาง

- ลูกศรขึ้น/ลง: เลื่อนเคอร์เซอร์
- `Tab` / `Shift+Tab`: เลื่อนไปมาระหว่างช่องของแบบฟอร์ม
- `Esc`: ย้อนกลับ (ยืนยันการออกเมื่ออยู่ที่หน้าจอหลัก)
- `a`: แสดงความช่วยเหลือ
- `t`: เปลี่ยนธีม
- `q`: ออก (ต้องยืนยัน)
- `r`: รีเฟรชการแสดงผล มีประโยชน์หลังปรับขนาดเทอร์มินัล
- `Ctrl+P`: พาเลตคำสั่ง (เปลี่ยนธีม ภาพหน้าจอ ความช่วยเหลือเรื่องแป้นลัด)

สลับธีมด้วย `t`: Omega-Stress ปรับสีและความละเอียดของการแสดงผลตามความสามารถของเทอร์มินัลที่ตรวจพบโดยอัตโนมัติ บนทุกหน้าจอ จากพาเลตคำสั่ง (`Ctrl+P` → ธีม) จะมีธีมให้เลือกครบทั้ง 31 ธีม (10 ธีม Omega + 21 ธีมในตัวของ Textual)

### เทอร์มินัลที่รองรับ

โปรไฟล์การแสดงผลสี่แบบ จากละเอียดที่สุดไปจนถึงลดทอนที่สุด: **ครบถ้วน** **มาตรฐาน** **ลดทอน** **ขาวดำ** โปรไฟล์ที่ใช้คือแบบที่เข้มงวดกว่าระหว่างตระกูลเทอร์มินัลที่ตรวจพบกับขนาดจริงของหน้าต่าง (ไม่ละเอียดเกินเพดานใดเพดานหนึ่ง)

| เทอร์มินัล | โปรไฟล์เริ่มต้น |
|---|---|
| Ghostty, Alacritty, WezTerm, Kitty | ครบถ้วน |
| Konsole, GNOME Terminal, Terminator, xfce4-terminal | มาตรฐาน |
| urxvt, xterm | ลดทอน |
| TTY ของ Linux | ขาวดำ |
| SSH (ตรวจพบ true color/256 สี) | ลดทอน |
| SSH (สัญญาณน้อยที่สุด) | ขาวดำ |
| เทอร์มินัลที่ไม่รู้จัก | ลดทอน (ค่าสำรองอย่างระมัดระวัง) |

เมื่อน้อยกว่า 80 คอลัมน์ × 24 บรรทัด จะมีหน้าจอเตือนก่อนหน้าจอหลัก (ไม่ขัดขวางการใช้งาน: แอปยังใช้ได้ในโหมดลดทอน) Konsole, GNOME Terminal และ Terminator ถูกระบุผ่านตัวแปรสภาพแวดล้อมเฉพาะของแต่ละตัว (`KONSOLE_VERSION`, `GNOME_TERMINAL_SCREEN`/`GNOME_TERMINAL_SERVICE`, `TERMINATOR_UUID`) แทน `TERM` ซึ่งเทอร์มินัลเหล่านี้ปล่อยไว้ที่ค่าทั่วไปเพื่อความเข้ากันได้ — xfce4-terminal ยังไม่มีเครื่องหมายเทียบเท่าที่ทราบ จึงได้โปรไฟล์มาตรฐานเดียวกันนี้ก็ต่อเมื่อมีค่า `TERM`/`TERM_PROGRAM` ที่จดจำได้เท่านั้น มิฉะนั้นจะเป็นลดทอน

### เส้นทางภายในและเส้นทางระบบ

โดยค่าเริ่มต้น Omega-Stress ทำงานในโฟลเดอร์ `var/` ของตัวเอง ซึ่งอิงกับไดเรกทอรีที่เริ่มโปรแกรม (หรือ `$OMEGA_STRESS_VAR_DIR` หากตั้งไว้):

```text
var/db/app.db           # ฐานข้อมูล SQLite (โปรไฟล์ เป้าหมาย ประวัติ)
var/settings.json       # การตั้งค่าที่บันทึกไว้ (ธีม โปรไฟล์การแสดงผล โฟลเดอร์เริ่มต้น)
var/exports/            # การส่งออก JSON/CSV/HTML เริ่มต้น
var/screenshots/        # ภาพหน้าจอ SVG เริ่มต้น (พาเลตคำสั่ง)
var/audit.jsonl         # บันทึกการตรวจสอบ (หนึ่งบรรทัดต่อการรัน)
var/app.log             # บันทึกของแอป
```

เส้นทางระบบแบบสัมบูรณ์ (เช่น `/var/exports/`) ไม่ถูกใช้เป็นค่าเริ่มต้นเลย — ดังนั้น `/` นำหน้าจึงมีความหมาย: มีเพียงการส่งออกที่ระบุอย่างชัดเจนไปยังโฟลเดอร์ที่ผู้ใช้เลือก (การตั้งค่าหรือหน้าจอส่งออก) เท่านั้นที่ออกไปนอกโฟลเดอร์นี้

## โปรไฟล์ระยะเวลา D1-D6 (โหมดโปรไฟล์)

ทางเลือกแทนโหมดกำหนดเอง (ระยะเวลา 1-5 นาที จำกัดตามระดับ): **โปรไฟล์ระยะเวลาที่มีชื่อ** มีระยะเวลารวมคงที่ และแบ่งภายในเป็น 4 ช่วง (วอร์มอัป ไต่ระดับ คงที่ ผ่อนลง) เลือกได้บนทุกหน้าจอเริ่มการทดสอบ (สวิตช์ “โหมดระยะเวลา: กำหนดเอง / โปรไฟล์ D1-D6”) และใน CLI ผ่าน `--duration-preset`

| โปรไฟล์ | ระยะเวลารวม | วอร์มอัป | ไต่ระดับ | คงที่ | ผ่อนลง | ระดับสูงสุดโดยไม่ต้องยืนยัน | ระดับเพิ่มเติม (ยืนยันแบบเข้มงวด) | กลุ่มที่ใช้ได้ |
|---|---|---|---|---|---|---|---|---|
| D1 (quick) | 1 นาที | 5 วินาที | 10 วินาที | 40 วินาที | 5 วินาที | สูงสุด | — | คำขอ การเชื่อมต่อ โหลด |
| D2 (short) | 5 นาที | 15 วินาที | 30 วินาที | 4 นาที | 15 วินาที | สูงสุด | — | คำขอ การเชื่อมต่อ โหลด |
| D3 (standard) | 15 นาที | 30 วินาที | 1 นาที 30 | 12 นาที 30 | 30 วินาที | รุนแรง | — | คำขอ การเชื่อมต่อ โหลด |
| D4 (resilience) | 30 นาที | 1 นาที | 3 นาที | 25 นาที | 1 นาที | รุกหนัก | รุนแรง | คำขอ การเชื่อมต่อ โหลด |
| D5 (extended) | 60 นาที | 2 นาที | 5 นาที | 51 นาที | 2 นาที | แรง | รุกหนัก | คำขอ การเชื่อมต่อ โหลด |
| D6 (soak) | 120 นาที | 3 นาที | 10 นาที | 104 นาที | 3 นาที | สูง | แรง | การเชื่อมต่อ โหลด (ไม่ใช้กับคำขอ) |

- ระดับ “เพิ่มเติม” (D4-D6) ใช้ได้ก็ต่อเมื่อพิมพ์ข้อความยืนยันแบบเข้มงวดที่แสดงบนหน้าจอให้ตรงทุกตัวอักษร — ไม่ใช่เพียงติ๊กช่อง
- D6 ไม่รวมการทดสอบคำขอ: การทดสอบปริมาณงานถูกจำกัดด้วยปริมาณรวม ซึ่งไม่มีความหมายสำหรับโปรไฟล์ 2 ชั่วโมงที่มุ่งดูการเปลี่ยนแปลงตามเวลา
- ตารางเดียวกันนี้ดูได้ในแอป (ช่วยเหลือ → โปรไฟล์ระยะเวลา D1-D6)

## โหมดความปลอดภัย

ช่องติ๊กบนทุกหน้าจอเริ่มการทดสอบ (ติ๊กไว้เป็นค่าเริ่มต้น) ซึ่งสลับ **เฉพาะ** ตัวป้องกันที่ปกป้องเครื่องที่รัน Omega-Stress (CPU/หน่วยความจำของตัวสร้างโหลดในเครื่อง):

- **ทำงานเสมอไม่ว่าการตั้งค่านี้จะเป็นอย่างไร**: เกณฑ์ที่ปกป้อง **เป้าหมายที่ถูกทดสอบ** (อัตราข้อผิดพลาด ค่าหน่วง) — การปิดเกณฑ์เหล่านี้ไม่มีความหมายสำหรับผลิตภัณฑ์ และไม่ใช่สิ่งที่ช่องนี้ควบคุม
- **เปิดโหมดความปลอดภัย (ค่าเริ่มต้น)**: การทดสอบจะหยุดอัตโนมัติหากเครื่องโฮสต์เองดูเหมือนรับภาระหนัก (CPU ของตัวสร้างโหลด และ CPU รวมของเครื่องสูงพร้อมกัน ไม่ใช่แค่อย่างใดอย่างหนึ่ง — การที่คอร์เดียวทำงานเต็มตามปกติไม่เพียงพอด้วยตัวเอง)
- **ปิดโหมดความปลอดภัย**: ตัวป้องกันในเครื่องนี้จะถูกนำออก จากนั้นจะแสดงข้อความเตือนที่เทียบระดับที่เลือกกับผลการปรับเทียบล่าสุดที่ทราบของเครื่องนี้ (ดู [การปรับเทียบในเครื่อง](#การปรับเทียบในเครื่อง)) — ยังคงเกินขอบเขตนั้นได้ แต่ความน่าเชื่อถือของผลลัพธ์และเสถียรภาพของเครื่องจะเป็นความรับผิดชอบของผู้ใช้

ใช้ได้ใน CLI ผ่าน `--unsafe` ด้วย (ค่าเริ่มต้นไม่ใส่ = เปิดโหมดความปลอดภัย)

## การปรับเทียบในเครื่อง

วัดความสามารถจริงของ **เครื่องนี้** (ไม่ใช่ของเป้าหมายที่ถูกทดสอบ): เซิร์ฟเวอร์ลูปแบ็กในเครื่องที่มีมาใน Omega-Stress จะรับโหลดที่เพิ่มขึ้นทีละขั้น ซึ่งสร้างโดยเอนจิน `httpx`/asyncio ตัวเดียวกับการทดสอบจริง

- 7 ขั้น ตั้งแต่ขณะว่าง (สัญญาณรบกวนพื้นหลังของระบบ) จนถึง 2000 การเชื่อมต่อ / 12,000 คำขอ/วินาที แต่ละขั้นถูกประเมินเทียบเกณฑ์สุขภาพ (CPU ของตัวสร้างโหลด และ CPU รวม หน่วยความจำที่เหลือ อัตราข้อผิดพลาด ปริมาณงานที่ทำได้) — 2 ขั้นสุดท้ายมีเงื่อนไข จะถูกข้ามหากขั้นก่อนหน้าไม่ปกติ
- สร้างขอบเขตที่ปลอดภัย (`VU_safe` / `RPS_safe`) จากขั้นปกติขั้นสุดท้าย พร้อมส่วนเผื่อความปลอดภัย (สำรองประมาณ 30 %) และระดับความเชื่อมั่นที่เพิ่มขึ้นตามความลึกที่ไปถึง
- **V1 วัดอย่างเดียว**: ผลลัพธ์ไม่ถูกนำไปจำกัดการทดสอบจริงโดยอัตโนมัติ — ใช้เป็นข้อมูลอ้างอิง โดยเฉพาะเมื่อปิด [โหมดความปลอดภัย](#โหมดความปลอดภัย)
- บันทึกแยกตามเครื่อง (ลายนิ้วมือแบบไม่ล่วงล้ำ: ระบบปฏิบัติการ/สถาปัตยกรรม/จำนวนคอร์/RAM ไม่เคยใช้ที่อยู่ฮาร์ดแวร์) เปิดดูได้ทุกเมื่อโดยไม่ต้องวัดใหม่

เข้าถึงได้จากหน้าจอ **การปรับเทียบ** ของ TUI (ปุ่ม “เริ่มการปรับเทียบ” แสดงความคืบหน้าทุกวินาที) หรือใน CLI:

```bash
omega-stress calibrate run     # เริ่มการปรับเทียบใหม่
omega-stress calibrate show    # แสดงผลการปรับเทียบล่าสุดที่ทราบ โดยไม่เริ่มใหม่
```

## การกำหนดค่า

ทุกอย่างตั้งค่าได้จากหน้าจอ **การตั้งค่า** ของ TUI (ไม่มีไฟล์กำหนดค่าให้แก้ด้วยมือ):

- **ธีม**: หนึ่งใน 10 ธีม Omega ใช้ทันทีและบันทึกไว้
- **โปรไฟล์การแสดงผล**: อัตโนมัติ (ตรวจจับเมื่อเริ่มโปรแกรม) หรือบังคับเอง (ครบถ้วน/มาตรฐาน/ลดทอน/ขาวดำ)
- **โฟลเดอร์ส่งออกเริ่มต้น**: กรอกช่อง “ปลายทาง” ของหน้าจอส่งออกไว้ให้
- **โฟลเดอร์ภาพหน้าจอเริ่มต้น**: ใช้โดยคำสั่ง “ภาพหน้าจอ” ของพาเลต (`Ctrl+P`)
- **การล้าง**: เป้าหมายล่าสุด (ไม่รวมที่ปักหมุด) เป้าหมายทั้งหมด (รวมที่ปักหมุดและการอนุญาตของเป้าหมายเหล่านั้น) หรือประวัติทั้งหมด — แต่ละอย่างมีการยืนยันแยกต่างหาก

การตั้งค่าถูกบันทึกใน `var/settings.json` ตัวโฟลเดอร์ราก `var/` เองเปลี่ยนเส้นทางได้ด้วยตัวแปรสภาพแวดล้อม `OMEGA_STRESS_VAR_DIR` (มีประโยชน์เพื่อแยกหลายอินสแตนซ์ หรือสำหรับการทดสอบ)

## การทดสอบและคุณภาพ

```bash
pytest
ruff check .
mypy src
lint-imports   # ตรวจ Dependency Rule (ดู pyproject.toml [tool.importlinter])
```

ชุดทดสอบมีมากกว่า 570 การทดสอบ (หน่วย การรวมระบบ TUI CLI) `lint-imports` จะทำให้ CI ล้มเหลวหากละเมิด Dependency Rule หรือการแยกเทคโนโลยีภายนอก — ดู [สถาปัตยกรรม](#สถาปัตยกรรม)

## การถอนการติดตั้ง

Omega-Stress ไม่แตะต้องสิ่งใดนอกโฟลเดอร์ของตัวเองและบรรทัดชื่อแทนที่เลือกเพิ่มได้:

```bash
rm -rf ~/omega-stress
sed -i '/alias stress=/d' ~/.bashrc ~/.zshrc
```

`install.sh` ไม่สร้างแพ็กเกจระบบ บริการ หรือไฟล์ใดนอก `~/omega-stress/` — ไม่ต้องถอนการติดตั้งเพิ่มเติม

## ข้อจำกัดที่ทราบ

- สร้างโหลด **ภายในโปรเซสเดียว** บนเครื่องเดียว (`httpx`/asyncio): ไม่ใช่เครื่องมือแบบกระจาย — เพดานจริง (ดู [ค่าของการทดสอบ](#ค่าของการทดสอบ)) ต่ำกว่าบริการทดสอบโหลดแบบ SaaS (loader.io ฯลฯ) อย่างชัดเจน โดยเจตนา ตามจุดยืนผลิตภัณฑ์ที่มีการควบคุม บนฮาร์ดแวร์ทั่วไป ระดับรุกหนัก/รุนแรง/สูงสุดของการทดสอบการเชื่อมต่ออาจใช้เวลาจริงนานกว่าระยะเวลาที่เลือกอย่างเห็นได้ชัดเพื่อส่งโหลดทั้งหมดที่ตั้งเป้าไว้ — ในกรณีนั้นความสามารถของ **เครื่องนี้** ไม่ใช่ของเป้าหมาย ที่จำกัดปริมาณงานจริง ใช้ [การปรับเทียบในเครื่อง](#การปรับเทียบในเครื่อง) เพื่อทราบค่าที่เหมาะสมกับฮาร์ดแวร์ของคุณ
- การตรวจจับตระกูลเทอร์มินัลอัตโนมัติอาศัยตัวแปรสภาพแวดล้อม: xfce4-terminal ยังไม่มีเครื่องหมายที่เชื่อถือได้ที่ทราบ (ดู [เทอร์มินัลที่รองรับ](#เทอร์มินัลที่รองรับ))
- `plugins/` เป็นจุดขยายที่สถาปัตยกรรมเตรียมไว้ (การโหลดปลั๊กอินในตัว/ภายนอก) ยังไม่ได้ทำใน V1: มีโครงแล้ว แต่ไม่มีปลั๊กอินใดมาให้
- `var/` อิงกับโฟลเดอร์โปรเจกต์ (ไม่ใช่ XDG): ออกแบบมาสำหรับผู้ใช้คนเดียวในเครื่อง ไม่ใช่การใช้ร่วมกันหลายผู้ใช้บนเครื่องเดียวกัน
- การทดสอบโหลด (เพิ่มขึ้นทีละขั้น) ใน **โหมดกำหนดเอง** ไม่มีขั้นลดโหลด (“cooldown”) หลังช่วงคงที่ — มีเฉพาะผ่าน [โปรไฟล์ระยะเวลา D1-D6](#โปรไฟล์ระยะเวลา-d1-d6-โหมดโปรไฟล์) ซึ่งรวมทั้ง 4 ช่วงไว้แล้ว
- การตรวจล่วงหน้าที่ผ่านแล้วไม่ผูกกับเป้าหมายใดเป้าหมายหนึ่ง: ใช้ได้ 24 ชม. สำหรับการเริ่มระดับรุนแรง/สูงสุดครั้งถัดไปทุกครั้ง ไม่ใช่เฉพาะเป้าหมายที่ตรวจไว้
- [การปรับเทียบในเครื่อง](#การปรับเทียบในเครื่อง) วัดค่า แต่ยังไม่นำขอบเขตที่ปลอดภัยไปจำกัดการทดสอบจริงโดยอัตโนมัติ — งานนี้แยกไว้ต่างหากโดยเจตนาและยังไม่ได้เริ่ม
