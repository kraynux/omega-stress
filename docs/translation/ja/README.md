**Omega-Stress** はローカルのターミナルアプリケーション（[Textual](https://github.com/Textualize/textual) による TUI + スクリプト可能な CLI）で、範囲を定めた再現可能な HTTP 負荷テストを統制します。固定プロファイル、履歴、再実行、詳細なエクスポート（JSON/CSV/HTML）、明確な安全上の上限を備えています。

このプロジェクトは **Clean Architecture** の原則に従い、業務ドメイン、オーケストレーション、インフラストラクチャ、ユーザーインターフェースを明確に分離しています。

## 概要

### 目的

## Omega-Stress ができること（V1 の目標）

- 制御された 3 つのテストファミリー: **リクエストテスト**（スループット）、**接続テスト**（同時接続数）、**負荷テスト**（段階的な増加）。
- **8 段階の強度**（微弱/低/中/高/強力/アグレッシブ/激烈/最大）と 3 段階の事前チェックモデル（不要 / 任意で必須 / 常に必須 — [テストの値](#テストの値) を参照）。
- **2 つの時間モード**: 手動（1〜5 分、レベルごとに上限あり）または **名前付きプロファイル D1-D6**（ウォームアップ/上昇/定常/下降を含む固定の合計時間 — [時間プロファイル D1-D6](#時間プロファイル-d1-d6プロファイルモード) を参照）。
- **安全モード**（既定で有効、起動ごとに無効化可能）: ホストマシンの CPU/メモリを守るローカルの保護で、テスト対象を守るしきい値とは別物です — [安全モード](#安全モード) を参照。
- **保存されるローカルキャリブレーション**: ローカルのループバックサーバーに段階的に負荷をかけ、ホストマシン（対象ではない）の実際の能力を測定します — [ローカルキャリブレーション](#ローカルキャリブレーション) を参照。
- 固定され、再利用でき、履歴に残るプロファイル — **任意**: プロファイルなしでも、対象を直接選ぶか入力すれば、手動モードでテストは問題なく動作します。
- ピン留めされていない対象に対しては、実行のたびに明示的な許可の確認が必須です。
- 自動停止のしきい値があり、上限のない負荷は決してかけません。
- 詳細な JSON/CSV/HTML エクスポート（ステップ、間隔ごとの指標、判定、診断）。
- 自動化（cron、CI）向けの非対話 CLI モード。TUI とまったく同じユースケースを呼び出します。
- ターミナルへの自動適応（テーマ + 簡略化可能な表示プロファイル）。

## このプロジェクトがしないこと

- ネットワークスキャンツールの代わりにはなりません — 語彙と製品の立ち位置はあえて「負荷テスト」であり、「スキャン」ではありません。
- 外部の負荷エンジン（k6 など）は実装しません — `httpx`/asyncio によるネイティブな負荷生成です。
- 上限と許可の確認なしに実行を始めることは決してありません。
- 分散型の負荷ツールではありません: 負荷生成は 1 台のマシン、1 つのプロセスで動作します — [既知の制限](#既知の制限) を参照。

## 機能

- **3 つのテストファミリー**、それぞれに 8 段階の強度（微弱/低/中/高/強力/アグレッシブ/激烈/最大）— 各レベルの正確な値は [負荷の目安](#テストの値) の表を参照。
- **固定テストプロファイル**: 名前、対象、ファミリー、強度、時間、エラーしきい値 — 一度作成すれば、TUI または CLI から同一条件で再実行できます。
- **名前付き時間プロファイル D1-D6**（「プロファイル」モード）、手動モードの代替: ウォームアップ/上昇/定常/下降を含む固定の合計時間（1〜120 分）で、利用できるレベルも制限されます — [時間プロファイル D1-D6](#時間プロファイル-d1-d6プロファイルモード) を参照。
- **安全モード**、すべての起動画面で既定でチェック済み: ホストマシン（対象ではない）が危険にさらされていると見られる場合にテストを中断します。理解した上で無効化でき、その際は選んだレベルと直近のキャリブレーションを比較する注意書きが表示されます — [安全モード](#安全モード) を参照。
- **保存されるローカルキャリブレーション**: マシンが実際にどこまで耐えられるかを測定し（組み込みのローカルループバックサーバーに対して 7 段階の増加する負荷）、キャリブレーション画面から参照できます — [ローカルキャリブレーション](#ローカルキャリブレーション) を参照。
- **ピン留めされた対象**: ピン留めしたアドレスは起動のたびに許可をチェックし直す必要がありません。ピン留めされていない最近の対象は表示されたまま（最大 10 件）ですが、暗黙の許可はありません。ピン留めされた対象は互いに独立した 2 つの使い方ができます: プロファイルなしの手動モードでテストを直接起動する、または固定プロファイル作成時の既定の対象として使う。
- **完全な履歴**: すべての実行が記録されます（判定、指標、間隔ごとの時系列、使用した安全モード）。固定プロファイルに紐づく実行は同一条件で再実行できます。
- **詳細なエクスポート**: JSON（再インポート可能な生データ）、CSV（表形式の分析）、HTML（読みやすいレポート、プロジェクトの 10 パレットからテーマを選択）。HTML レポートは設定で選んだ言語（「エクスポートの言語」、既定ではインターフェースと同じ）で書かれます。JSON と CSV はデータのままで、翻訳されません。
- **事前チェック**: 激烈/最大のテストの前には毎回自動かつ必須、強力/アグレッシブでは任意（ただし長い時間が解放されます）。有効期間（24 時間）があります。
- 実行中テストの**リアルタイム監視**: 信頼できるカウントダウン付きの進捗表示（残り時間は推定ではなく直接計算）、スループット/エラー/p95 レイテンシを間隔ごとに更新、アプリを終了せずに手動停止できます。
- **一元化された設定**: テーマ（Omega の 10 パレット + Textual のすべての組み込みテーマ、コマンドパレットから合計 31）、表示プロファイル（自動または固定）、エクスポートとスクリーンショットのフォルダー、対象/履歴の消去。
- **組み込みヘルプ**（`a` キー）: キーボードショートカット、各画面の説明（キャリブレーションと安全モードを含む）、負荷値の参照表、時間プロファイル D1-D6 の表。
- **スクリプト可能な CLI**（`omega-stress profile|run|history|export|calibrate ...`）、TUI とまったく同じユースケースで、自動化向けに `--json` 出力があります。
- **ターミナルへの自動適応**: 起動時に種類とサイズを検出し、テーマと表示の豊かさを調整します（[対応ターミナル](#対応ターミナル) を参照）。

## アーキテクチャ

Clean Architecture + Ports & Adapters による 9 つのパッケージ（`app/`、`core/`、`domain/`、`application/`、`ports/`、`infrastructure/`、`interfaces/`、`plugins/`、`shared/`）。
詳細: `ARCHITECTURE.md`。

```text
src/omega_stress/
├── app/              ブートストラップと依存性注入コンテナ（手動の組み立て、DI フレームワークなし）
├── core/             横断的な語彙: 列挙型、ルート例外、Result/Ok/Err、システムの能力
├── domain/           純粋な業務ロジック: 負荷、プロファイル、実行、対象、テーマ、ターミナル — I/O なし
├── application/      オーケストレーション: commands（操作）、queries（読み取り）、実行パイプライン（guards/hooks）
├── ports/            アダプターが期待する Protocol/ABC の契約（リポジトリ、エクスポーター、負荷生成器...）
├── infrastructure/   具体的な実装: SQLite、JSON/CSV/HTML エクスポーター、httpx/asyncio 生成器、ターミナル検出、システムプローブ
├── interfaces/       独立した 2 つの表示アダプター: TUI（Textual）と CLI（argparse）
├── plugins/          予約済みの拡張ポイント（プラグイン読み込み）— 骨組みはあるが V1 では未実装
└── shared/           業務に依存しない横断ユーティリティ（注入可能な時計、識別子の生成）
```

### 設計原則

- `domain/` には I/O もインフラへの依存もありません — 純粋な業務ロジックで、モックなしで完全にテストできます。
- `application/` はドメインとポートを通じてユースケースを統制し、`infrastructure/` の具体クラスを直接使うことはありません。
- `infrastructure/` はポートを実装し、`application/` や `domain/` から直接インポートされることはありません — 参照するのは `interfaces/` と `app/` だけです。
- `interfaces/` は `infrastructure/` や `subprocess` を直接呼び出してはいけません: `application/`（commands/queries）と自身のコントローラーを通すだけです。
- `ports/` はアダプターが期待する契約（Protocol）を定義し、実装は決して持ちません。
- `core/` はすべての層で共有される語彙をまとめますが、数値を伴う業務ルール（しきい値、時間、プリセット — 常に `domain/*/policies.py` にある）は決して含みません。

Dependency Rule（外側の層から内側の層へのみ）とサードパーティ技術の隔離（`textual`、`sqlite3`、`httpx`、`jinja2` はそれぞれ決められた入口に限定）は、`lint-imports` を実行するたびに自動で検証されます（[テストと品質](#テストと品質) を参照）。

## インストール

公式アーカイブは `.tar.gz` 形式で提供されます。インストール前に完全性を確認してください:

```bash
sha256sum omega-stress.tar.gz
```

### 方法 1 — インストールスクリプト

```bash
[ -d omega-stress ] && echo "ℹ️ すでにここに展開済みのため、この手順を省略します。" || tar -xzf omega-stress.tar.gz
[ -d ~/omega-stress ] && echo "ℹ️ ~/omega-stress がすでにあるため、移動を省略します。" || mv omega-stress ~/
cd ~/omega-stress/
chmod +x install.sh
./install.sh
```

### 方法 2 — 堅牢な一括インストール

このコマンドはそのままコピー＆ペーストでき、何度実行してもエラーになりません: 各手順はすでに済んだ処理を省略します。

```bash
( [ -d omega-stress ] || tar -xzf omega-stress.tar.gz ) && \
( [ -d ~/omega-stress ] || mv omega-stress ~/ ) && \
cd ~/omega-stress && chmod +x install.sh && ./install.sh
```
`install.sh`:

1. 仮想環境 `.venv` がなければ作成します。
2. 依存関係をインストールします（`pip install -e .`。`pyproject.toml` が唯一の正となる情報源です）。
3. `omega-stress.sh` と `install.sh` を実行可能にします。
4. エイリアス `stress` を `~/.bashrc` と `~/.zshrc` に追加します（すでにあれば重複させません）。

### インターフェースの言語

インターフェースは 17 言語で利用できます: フランス語、英語、スペイン語、ポルトガル語（ブラジル）、イタリア語、ドイツ語、オランダ語、ポーランド語、ロシア語、簡体字中国語、ベトナム語、タイ語、インドネシア語、日本語、韓国語、ヒンディー語、アラビア語。設定（「Langue / Language」）で選択し、インターフェースの再起動後に反映されます。変数 `OMEGA_STRESS_LANG`（例: `OMEGA_STRESS_LANG=ja ./omega-stress.sh`）で 1 セッションだけ言語を指定できます。omega-suite から起動した場合、omega-stress はスイートの言語を使います。Linux のテキストコンソール（TTY）では、ラテン文字以外の言語はそのセッションの間、英語で表示されます。コマンドラインはフランス語のままです。

### CLI での使い方

```bash
omega-stress profile list                                     # プロファイルの一覧
omega-stress profile create --name "API 調査" --target-id t-1 \
    --family request --level bas --duration-minutes 1 --max-error-rate 0.05
omega-stress profile freeze <profile-id>                       # プロファイルを固定

# 激烈/最大の起動前には毎回事前チェックが必須（強力/アグレッシブでは任意）
omega-stress run precheck --target-id t-1 --target-url https://exemple.org --confirm

omega-stress run request --target-id t-1 --target-url https://exemple.org \
    --level bas --duration-minutes 1 --max-error-rate 0.05 --confirm
omega-stress run connection --target-id t-1 --target-url https://exemple.org \
    --level moyen --duration-minutes 3 --max-error-rate 0.05 --confirm
omega-stress run ramp --target-id t-1 --target-url https://exemple.org \
    --level puissant --duration-minutes 3 --max-error-rate 0.05 --confirm --precheck-validated

# --duration-minutes の代わりにプロファイルモード D1-D6（同時指定不可）
# D4 (resilience) はアグレッシブを無条件で、激烈を強化確認つきで許可
omega-stress run request --target-id t-1 --target-url https://exemple.org \
    --level violent --duration-preset d4 --max-error-rate 0.05 --confirm \
    --precheck-validated --confirmation-text JE_CONFIRME_LA_CIBLE_AUTORISEE

# --unsafe は安全モード（ローカルの CPU/メモリ保護）を無効化。既定では指定なし
omega-stress run connection --target-id t-1 --target-url https://exemple.org \
    --level violent --duration-minutes 1 --max-error-rate 0.05 --confirm \
    --precheck-validated --unsafe

omega-stress run replay <run-id> --confirm                     # 固定プロファイルに紐づく実行を再実行

omega-stress history list                                      # 実行履歴
omega-stress history show <run-id>                              # 実行の詳細

omega-stress export <run-id> --format html --destination var/exports --theme omega-base

omega-stress calibrate run                                      # このマシンのキャリブレーションを実行
omega-stress calibrate show                                     # 既知の最新キャリブレーションを表示
```

`--level` の値（`faible`、`bas`、`moyen`、`haut`、`puissant`、`agressif`、`violent`、`maximum`）と確認テキストは、コマンドラインの他の部分と同じくフランス語のままです。

`--confirm` は TUI の許可チェックボックスに相当するコマンドライン上の指定です: 許可済みとしてピン留めされていない対象には必須です。`--target-id`/`--target-url` が同一なら手動（ピン留めなし）の対象を意味します。起動のたびに `--confirm` を付けずに済むよう、すでにピン留めされた対象の識別子を使ってください。

`history`/`export`/`calibrate` に `--json` を付けると機械可読な出力になり、cron/CI で便利です。

### 典型的な流れ

1. 初回起動時、メイン画面には次が表示されます: プロファイル、リクエストテスト、接続テスト、負荷テスト、履歴、対象、キャリブレーション、設定、ヘルプ。
2. テスト画面では、上部で固定プロファイル（任意）を選ぶこともできます: 対象と条件を指定する 2 つの方法で、1 回の起動で併用されることはありません —
   - **プロファイルあり**: 選ぶと対象/強度/時間/エラーしきい値が入力され、手動の対象欄は消えます（不要になるため）。入力された値は起動前に変更できます。
   - **プロファイルなし（手動モード）**: ピン留め/最近の対象を一覧から選ぶか新たに入力し、許可済みとしてピン留めされていなければ許可をチェックし、強度/時間（手動または時間プロファイル D1-D6）/エラーしきい値を自分で設定します。

   どちらの場合も: 安全モードを有効のままにするか理解した上で無効化し、レベルが求めるなら事前チェックを行い、テストを起動します。
3. 結果は履歴を経由せずにすぐ表示されます（判定、指標、時系列）— エクスポートはこの画面から直接行えます。
4. プロファイルを固定しておけば、プロファイル画面から、または履歴から再実行して、同じテストを後で同一条件で実行できます。

### テストの値

8 段階の強度は 3 つのテストファミリーで共通です（制御する次元だけが異なります）— 完全な表:

| テストの種類 | レベル | 制御する次元 | 目標値 | 事前チェック | 利用できる時間（手動モード） |
|---|---|---|---|---|---|
| リクエストテスト | 微弱 | スループット | 250 req/分（≈4.2 req/秒） | 不要 | 1〜5 分 |
| リクエストテスト | 低 | スループット | 500 req/分（≈8.3 req/秒） | 不要 | 1〜5 分 |
| リクエストテスト | 中 | スループット | 1000 req/分（≈16.7 req/秒） | 不要 | 1〜5 分 |
| リクエストテスト | 高 | スループット | 2000 req/分（≈33.3 req/秒） | 不要 | 1〜5 分 |
| リクエストテスト | 強力 | スループット | 6000 req/分（≈100 req/秒） | 任意 | 1〜3 分（事前チェック合格で 5 分） |
| リクエストテスト | アグレッシブ | スループット | 10,000 req/分（≈167 req/秒） | 任意 | 1〜3 分（事前チェック合格で 5 分） |
| リクエストテスト | 激烈 | スループット | 15,000 req/分（≈250 req/秒） | **必須** | 1〜3 分のみ |
| リクエストテスト | 最大 | スループット | 20,000 req/分（≈333 req/秒） | **必須** | 1〜3 分のみ |
| 接続テスト | 微弱 | 同時接続数 | 25 接続 | 不要 | 1〜5 分 |
| 接続テスト | 低 | 同時接続数 | 50 接続 | 不要 | 1〜5 分 |
| 接続テスト | 中 | 同時接続数 | 100 接続 | 不要 | 1〜5 分 |
| 接続テスト | 高 | 同時接続数 | 200 接続 | 不要 | 1〜5 分 |
| 接続テスト | 強力 | 同時接続数 | 1000 接続 | 任意 | 1〜3 分（事前チェック合格で 5 分） |
| 接続テスト | アグレッシブ | 同時接続数 | 2000 接続 | 任意 | 1〜3 分（事前チェック合格で 5 分） |
| 接続テスト | 激烈 | 同時接続数 | 3500 接続 | **必須** | 1〜3 分のみ |
| 接続テスト | 最大 | 同時接続数 | 5000 接続 | **必須** | 1〜3 分のみ |
| 負荷テスト（段階的な増加） | 微弱 | スループット、段階的に上昇 | ピーク 250 req/分 | 不要 | 1〜5 分 |
| 負荷テスト（段階的な増加） | 低 | スループット、段階的に上昇 | ピーク 500 req/分 | 不要 | 1〜5 分 |
| 負荷テスト（段階的な増加） | 中 | スループット、段階的に上昇 | ピーク 1000 req/分 | 不要 | 1〜5 分 |
| 負荷テスト（段階的な増加） | 高 | スループット、段階的に上昇 | ピーク 2000 req/分 | 不要 | 1〜5 分 |
| 負荷テスト（段階的な増加） | 強力 | スループット、段階的に上昇 | ピーク 6000 req/分 | 任意 | 1〜3 分（事前チェック合格で 5 分） |
| 負荷テスト（段階的な増加） | アグレッシブ | スループット、段階的に上昇 | ピーク 10,000 req/分 | 任意 | 1〜3 分（事前チェック合格で 5 分） |
| 負荷テスト（段階的な増加） | 激烈 | スループット、段階的に上昇 | ピーク 15,000 req/分 | **必須** | 1〜3 分のみ |
| 負荷テスト（段階的な増加） | 最大 | スループット、段階的に上昇 | ピーク 20,000 req/分 | **必須** | 1〜3 分のみ |

- **事前チェック 不要**: テストはすぐに始まり、時間に関する条件はありません。
- **事前チェック 任意**（強力/アグレッシブ）: 事前チェックなしでもテストは始まります（時間 1〜3 分）が、事前チェックに合格すると 4〜5 分の時間も解放されます。
- **事前チェック 必須**（激烈/最大）: 合格した事前チェックがなければテストは始まりません。事前チェックがあっても時間は 3 分が上限のままです（ここでは事前チェックはレベルへのアクセスを左右するもので、時間の延長ではありません）。

上の「利用できる時間」の列は **手動モード** だけを対象としています（最大 5 分）。それを超えるには [プロファイルモード D1-D6](#時間プロファイル-d1-d6プロファイルモード) だけがより長いテスト（最大 120 分）を可能にします — その時間でどのレベルが利用できるかは各プロファイル D1-D6 自体が決めます（`free_max_level`/`reinforced_level`、プロファイル専用の表を参照）:

| レベル | 手動モードでの最大時間 | プロファイル D1-D6 での最大時間 |
|---|---|---|
| 微弱 / 低 / 中 / 高 | 5 分 | 120 分（D6、接続/負荷のみ）。リクエストは 60 分（D5。D6 はこのファミリーに非対応） |
| 強力 | 5 分（事前チェックなしは 3 分） | 強化確認ありで 120 分（D6、接続/負荷）、なしで 60 分（D5） |
| アグレッシブ | 5 分（事前チェックなしは 3 分） | 強化確認ありで 60 分（D5）、なしで 30 分（D4） |
| 激烈 | 3 分（事前チェック必須） | 強化確認ありで 30 分（D4）、なしで 15 分（D3） |
| 最大 | 3 分（事前チェック必須） | 最大 5 分（D1/D2 のみ — 確認があっても D3-D6 のどのプロファイルも最大を提供しません） |

同じ表はアプリ内（ヘルプ → 負荷の目安）で直接参照でき、常に同じ参照値（`domain/load/presets.py`、`domain/load/policies.py`）から生成されます — 手で書き写すことはありません。

> **手動モード** の負荷テストでは、上昇と定常は選んだ時間に合わせて自動で伸縮されます（プリセットの比率を保ったまま）: 1 分のテストでも 0 からピークまで曲線全体をたどり、冒頭だけで終わることはありません。**プロファイルモード D1-D6** では、各プロファイルのウォームアップ/上昇/定常/下降の分割が、同じ保証を最初から与えます — [時間プロファイル D1-D6](#時間プロファイル-d1-d6プロファイルモード) を参照。

### 操作

- 上下の矢印: カーソル移動。
- `Tab` / `Shift+Tab`: フォームの欄の間を移動。
- `Esc`: 戻る（メイン画面では終了の確認）。
- `a`: ヘルプを表示。
- `t`: テーマを変更。
- `q`: 終了（確認あり）。
- `r`: 表示を更新。ターミナルのサイズ変更後に便利です。
- `Ctrl+P`: コマンドパレット（テーマ変更、スクリーンショット、ショートカットのヘルプ）。

`t` でテーマを切り替えられます: Omega-Stress はどの画面でも、検出したターミナルの能力に合わせて色と表示の豊かさを自動で調整します。コマンドパレット（`Ctrl+P` → テーマ）からは、利用できる 31 のテーマ（Omega 10 + Textual 組み込み 21）がすべて選べます。

### 対応ターミナル

最も豊かなものから最も簡略なものまで 4 つの表示プロファイル: **完全**、**標準**、**簡略**、**モノクロ**。使われるプロファイルは、検出したターミナルの種類と実際のウィンドウサイズのうち、より厳しい方です（どちらの上限よりも豊かになることはありません）。

| ターミナル | 既定のプロファイル |
|---|---|
| Ghostty、Alacritty、WezTerm、Kitty | 完全 |
| Konsole、GNOME Terminal、Terminator、xfce4-terminal | 標準 |
| urxvt、xterm | 簡略 |
| Linux の TTY | モノクロ |
| SSH（true color/256 色を検出） | 簡略 |
| SSH（最小限のシグナル） | モノクロ |
| 不明なターミナル | 簡略（慎重なフォールバック） |

80 列 × 24 行未満では、メイン画面の前に警告画面が表示されます（ブロックはしません: アプリは簡略モードで引き続き使えます）。Konsole、GNOME Terminal、Terminator は、互換性のため汎用値のままにされる `TERM` ではなく、それぞれ固有の環境変数（`KONSOLE_VERSION`、`GNOME_TERMINAL_SCREEN`/`GNOME_TERMINAL_SERVICE`、`TERMINATOR_UUID`）で識別されます — xfce4-terminal には今のところ同等の既知の目印がないため、認識できる `TERM`/`TERM_PROGRAM` の値を示す場合にのみ同じ標準プロファイルになり、それ以外は簡略になります。

### 内部パスとシステムパス

既定では、Omega-Stress は起動したディレクトリを基準とする自身の `var/` フォルダー（設定されていれば `$OMEGA_STRESS_VAR_DIR`）で動作します:

```text
var/db/app.db           # SQLite データベース（プロファイル、対象、履歴）
var/settings.json       # 保存された設定（テーマ、表示プロファイル、既定のフォルダー）
var/exports/            # 既定の JSON/CSV/HTML エクスポート
var/screenshots/        # 既定の SVG スクリーンショット（コマンドパレット）
var/audit.jsonl         # 監査ログ（実行ごとに 1 行）
var/app.log             # アプリケーションのログ
```

絶対システムパス（例: `/var/exports/`）が既定で使われることはありません — したがって先頭の `/` には意味があります: このフォルダーの外に出るのは、ユーザーが選んだフォルダー（設定またはエクスポート画面）への明示的なエクスポートだけです。

## 時間プロファイル D1-D6（プロファイルモード）

手動モード（時間 1〜5 分、レベルごとに上限あり）の代替: **名前付き時間プロファイル** は固定の合計時間を持ち、内部で 4 つのフェーズ（ウォームアップ、上昇、定常、下降）に分かれます。すべての起動画面（「時間モード: 手動 / プロファイル D1-D6」の切り替え）と CLI の `--duration-preset` で選べます。

| プロファイル | 合計時間 | ウォームアップ | 上昇 | 定常 | 下降 | 確認なしの最大レベル | 追加レベル（強化確認） | 対応ファミリー |
|---|---|---|---|---|---|---|---|---|
| D1 (quick) | 1 分 | 5 秒 | 10 秒 | 40 秒 | 5 秒 | 最大 | — | リクエスト、接続、負荷 |
| D2 (short) | 5 分 | 15 秒 | 30 秒 | 4 分 | 15 秒 | 最大 | — | リクエスト、接続、負荷 |
| D3 (standard) | 15 分 | 30 秒 | 1 分 30 秒 | 12 分 30 秒 | 30 秒 | 激烈 | — | リクエスト、接続、負荷 |
| D4 (resilience) | 30 分 | 1 分 | 3 分 | 25 分 | 1 分 | アグレッシブ | 激烈 | リクエスト、接続、負荷 |
| D5 (extended) | 60 分 | 2 分 | 5 分 | 51 分 | 2 分 | 強力 | アグレッシブ | リクエスト、接続、負荷 |
| D6 (soak) | 120 分 | 3 分 | 10 分 | 104 分 | 3 分 | 高 | 強力 | 接続、負荷（リクエストは不可） |

- 「追加」レベル（D4-D6）は、画面に表示される強化確認テキストを正確に入力した場合にのみ利用できます — 単なるチェックボックスでは決して利用できません。
- D6 はリクエストテストを除外します: スループットテストは総量で上限が決まり、時間経過によるずれを見る 2 時間のプロファイルには意味がありません。
- 同じ表はアプリ内（ヘルプ → 時間プロファイル D1-D6）で参照できます。

## 安全モード

すべての起動画面にあるチェックボックス（既定でチェック済み）で、Omega-Stress が動作するマシンを守る保護（ローカル生成器の CPU/メモリ）**だけ** を切り替えます:

- **この設定にかかわらず常に有効**: **テスト対象** を守るしきい値（エラー率、レイテンシ）— これを無効にすることは製品として決して意味をなさず、このチェックボックスの対象ではありません。
- **安全モード有効（既定）**: ホストマシン自体が苦しんでいると見られる場合、テストは自動で停止します（生成器の CPU とマシン全体の CPU が同時に高い場合で、どちらか一方だけではありません — 1 コアが普通に飽和するだけでは、それ自体では決して十分ではありません）。
- **安全モード無効**: このローカル保護が外されます。続いて、選んだレベルとこのマシンの既知の最新キャリブレーションを比較する注意書きが表示されます（[ローカルキャリブレーション](#ローカルキャリブレーション) を参照）— この安全上限を超えることは可能なままですが、結果の信頼性とマシンの安定性はユーザーの責任になります。

CLI では `--unsafe` でも利用できます（既定では指定なし = 安全モード有効）。

## ローカルキャリブレーション

**このマシン**（テスト対象ではない）の実際の能力を測定します: Omega-Stress に組み込まれたローカルのループバックサーバーが、実際のテストと同じ `httpx`/asyncio エンジンで生成される段階的に増える負荷を受けます。

- 7 ステップ、アイドル（システムの背景ノイズ）から 2000 接続 / 12,000 req/秒まで。各ステップは健全性のしきい値（生成器の CPU と全体の CPU、利用可能なメモリ、エラー率、達成スループット）で評価されます — 最後の 2 ステップは条件付きで、前のステップが健全でなければ省略されます。
- 最後の健全なステップから、安全マージン（約 30 % の余裕）と、到達した深さに応じて高まる信頼度を伴う安全上限（`VU_safe` / `RPS_safe`）を導きます。
- **V1 では測定のみ**: 結果は実際のテストを制限するために自動で適用されることはありません — 参考情報としての目安で、特に [安全モード](#安全モード) を無効にするときに役立ちます。
- マシンごとに保存され（非侵襲的なフィンガープリント: OS/アーキテクチャ/コア数/RAM、ハードウェアアドレスは決して使わない）、再測定せずにいつでも参照できます。

TUI の **キャリブレーション** 画面（「キャリブレーションを開始」ボタン、進捗を秒ごとに表示）、または CLI から利用できます:

```bash
omega-stress calibrate run     # 新しいキャリブレーションを実行
omega-stress calibrate show    # 新たに実行せず、既知の最新キャリブレーションを表示
```

## 設定

すべて TUI の **設定** 画面から行います（手で編集する設定ファイルはありません）:

- **テーマ**: Omega の 10 テーマのいずれか。すぐに適用され、保存されます。
- **表示プロファイル**: 自動（起動時に検出）または手動で固定（完全/標準/簡略/モノクロ）。
- **既定のエクスポートフォルダー**: エクスポート画面の「保存先」欄に事前入力されます。
- **既定のスクリーンショットフォルダー**: パレット（`Ctrl+P`）の「スクリーンショット」コマンドで使われます。
- **消去**: 最近の対象（ピン留めは決して含まない）、すべての対象（ピン留めとその許可を含む）、または履歴全体 — それぞれ個別の確認で保護されています。

設定は `var/settings.json` に保存されます。ルートの `var/` 自体も環境変数 `OMEGA_STRESS_VAR_DIR` で移動できます（複数のインスタンスを分けたいときや、テストに便利です）。

## 既知の制限

- 負荷生成は 1 台のマシン上の **同一プロセス内**（`httpx`/asyncio）で行われます: 分散ツールではありません — 実際の上限（[テストの値](#テストの値) を参照）は SaaS の負荷テストサービス（loader.io など）よりかなり控えめで、これは制御された製品という立ち位置による意図的なものです。控えめなハードウェアでは、接続テストのアグレッシブ/激烈/最大は、目標とする負荷をすべて送るのに選んだ時間より明らかに長い実時間がかかることがあります — その場合、実際のスループットを制限しているのは対象ではなく **このマシン** の能力です。お使いのハードウェアに合った値を知るには [ローカルキャリブレーション](#ローカルキャリブレーション) を使ってください。
- ターミナルの種類の自動検出は環境変数に頼っています: xfce4-terminal には今のところ信頼できる既知の目印がありません（[対応ターミナル](#対応ターミナル) を参照）。
- `plugins/` はアーキテクチャが想定する拡張ポイント（組み込み/外部プラグインの読み込み）ですが、V1 では未実装です: 骨組みはありますが、プラグインは同梱されていません。
- `var/` はプロジェクトフォルダーを基準にします（XDG ではありません）: 単一ユーザーのローカル利用向けに設計されており、同じマシンでの複数ユーザー共有向けではありません。
- **手動モード** の負荷テスト（段階的な増加）には、定常の後の下降ステップ（「cooldown」）がありません — それは 4 つのフェーズをすでに含む [時間プロファイル D1-D6](#時間プロファイル-d1-d6プロファイルモード) でのみ利用できます。
- 合格した事前チェックは特定の対象に結びつきません: 確認した対象だけでなく、以後のすべての激烈/最大の起動に 24 時間有効です。
- [ローカルキャリブレーション](#ローカルキャリブレーション) は測定しますが、その安全上限を実際のテストの制限として自動適用することはまだありません — 意図的に切り分けられた作業で、まだ着手していません。
